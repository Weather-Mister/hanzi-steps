# Book 1 controlled-production audit

Baseline: main 3fc810f. Prototype gate: Units 11, 29 and 48, followed by an individual audit of Units 1–48.

The release adds 65 short tasks, with 106 explicitly authored full response forms. Units 1–7 have none; Units 8–20 have at most one each; later units have one to three. Tasks occupy separate lesson tails; no lesson has more than one. The longest canonical response has 24 Han characters. Original lesson prefixes, vocabulary, characters, grammar, phrases and IDs are unchanged.

Difficulty describes prompt freedom, rather than a rigid unit boundary. Visible constraints bound exact grading. Reordering, synonyms, dropped subjects and optional particles count only where the prompt permits them and a full response is authored. 台灣 is an explicit Traditional spelling alternative in two residence prompts; 台湾 still fails. No conversion or inferred alternatives are used.

## Deliberate omissions and coverage

Units 26, 34, 37, 38, 41 and 44 retain only one useful short task. A second greeting, immediate dialogue repetition, similar construction or copied passage would add little. Cultural, proper-name, role-label and support-only cards are excluded. Some productive models are new transfer sentences composed from already taught words and constructions; an exact sentence need not previously have been displayed. All answer glyphs and declared grammar must be taught, except the two reviewed Taiwan spelling aliases.

Placement checks require at least three intervening steps since the last exact full-answer display, append-only placement, a productive canonical phrase, and a reconstructible fallback. The frozen main fixture checks every original step hash, partial index and completion length. Legitimate authored variants include time/conditional subject positions, optional repeated subjects, bounded question endings and all six orders of the three recovery suggestions. No unbounded autobiographical answer is graded as exact recall.

## UX and mastery

The initial exercise has no answer bank, phrase/audio/pinyin card or pattern card. The first hint is English. Chinese vocabulary or builder material requires a learner-entered Chinese draft first. Any help remains assisted through retry, pause and reload; a wrong check records a failed attempt and makes recovery assisted. Composition disables checking, Enter does not submit, and the labeled textarea does not open the keyboard automatically. Feedback says an unlisted response did not match a reviewed form, displays an example, and offers retry/help.

Production uses existing sentence skills, linked grammar/usage records, practice queues, lesson counts and RPCs. The birthday greeting uses its canonical vocabulary/input skill to avoid an unreachable duplicate phrase skill. No separate production learner state is created.

## Verification

- Grading fixtures reject Simplified glyphs, omitted words, bad order/grammar, unsupported synonyms, digits and Unicode compatibility folds. All authored variants and harmless spacing/punctuation pass.
- Content/prerequisite, mastery, density, immutable-prefix and database-metadata checks pass. Legacy topology guards still freeze every pre-production activity, while the new fixture independently verifies the append-only additions.
- Browser tests cover 360/390px and desktop, representative accepted variants for every prototype prompt, no answer leaks, IME, progressive help/fallback, duplicate checks, sticky assistance after reload, historical completion, and signed-in progress/mastery RPC payloads. RPCs are mocked; no synthetic attempts go to a live learner account.
- Isolated PostgreSQL/PGlite executes the actual migration and save function over every configured current/historical bound. It verifies old queued completions, unfinished tails, retry dates, completion monotonicity, ownership and malformed checkpoints. The fixture substitutes the unchanged account resolver. All synthetic records roll back; the supplied SQL can verify actual staging RPCs too.
- TypeScript, curriculum generation/validation, character coverage and the Pages build pass. Full suite: 430 passed, 13 failed, one skipped. Untouched main: 423 passed, the same 13 failed, one skipped. Exact failure-name comparison found no new failures. The two database-metadata tests added after that run also pass; the focused production/mastery/progress/lossless gate has 38 passes and one skip.

These checks establish consistency and answer coverage for the authored frames. Actual difficulty, typing time and keyboard feel on real iOS/Android devices require learner feedback. Density stays provisional.

## Release order

Apply `supabase/migrations/20261004024116_controlled_production_progress_compat.sql` before publishing the frontend. It updates private curriculum metadata and validation without rewriting learner rows or changing auth/RPC permissions. Then run `supabase/verify-production-progress.sql` in staging (transactional rollback), publish and check an old incomplete lesson, old completion and offline retry on two devices.

For isolated reproduction, install `@electric-sql/pglite` outside the app and run `HANZI_PGLITE_MODULE=<its ESM entry> node scripts/verify-production-postgres.mjs`. The Playwright browser runner is `tests/browser/production.cjs`; optional `HANZI_PLAYWRIGHT` and `HANZI_CHROMIUM` point to an installed test runtime/browser.

Database migration and frontend deployment are prepared, not applied by this branch.
